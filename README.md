# LanxinBansai V1

东莞篮球一句话约战微信小程序演示版。

这是一个围绕“用户一句话描述需求，小程序自动匹配方案”的前台演示项目，面向东莞本地篮球活动场景，当前版本聚焦产品体验展示、资源编排演示和线索收集，不接真实后端、不接支付、不做真实锁单。

## 项目定位

- 城市范围固定为东莞
- 核心能力是“一句话匹配整套方案”
- 首页主流程优先服务两类场景：
  - 半专业赛事
  - 野球约球
- 输出闭环分为两条：
  - 生成分享海报
  - 填写预约信息

## 当前页面结构

- 首页 `pages/index/index`
  - 先选择约战方式
  - 选中后页面中部上移并展开一句话需求输入
  - 支持点击示例需求直接填充
  - 当信息不完整时使用底部补齐弹层继续补问
- 推荐方案页 `pages/result/result`
  - 输出主方案、重点项、资源卡片、备选方向
  - 支持重新匹配需求
  - 支持填写预约信息
  - 支持进入海报页
- 历史方案页 `pages/history/history`
  - 只展示推荐记录和预约记录的前 4 条预览
  - 标题右侧提供“查看更多”入口
- 更多记录页 `pages/records/records`
  - 支持查看完整推荐记录或完整预约记录
  - 支持按地点、日期筛选
- 资源库页 `pages/library/library`
  - 独立浏览场馆、裁判、物料、租赁、供应商、媒体
  - 支持分类切换
  - 支持镇区筛选
- 海报页 `pages/poster/poster`
  - 展示方案封面
  - 支持小程序转发
  - 支持保存海报
  - 远程封面图加载失败时仍可继续导出

## 核心产品逻辑

### 1. 模式选择

当前首页固定两种模式：

- 半专业赛事
  - 更偏企业赛、园区赛、社区联赛
  - 输出内容更完整，包含场馆、裁判、物料、租赁、供应商、媒体建议
- 野球约球
  - 更偏朋友组局、半场对抗、轻量约战
  - 输出内容更轻量，聚焦场馆、裁判和基础物料租赁

### 2. 一句话解析

当前版本使用本地规则解析，不依赖真实大模型。

在 `utils/parser.js` 中会识别：

- 镇区
- 日期
- 预算档位
- 人数
- 队伍数
- 是否需要裁判
- 是否需要物料
- 是否需要媒体
- 是否需要执行
- 室内/室外偏好

当前已根据产品反馈调整为：

- 首页首轮补齐不再强制追问“室内/室外”
- 因为当前资源大部分为室内馆，优先降低用户输入门槛
- 后续仍可在结果页通过“重新匹配需求”进行场地偏好调整

### 3. 方案推荐

在 `utils/recommender.js` 中通过本地规则引擎完成推荐：

- 场馆先根据模式、预算、镇区、人数、室内外偏好打分
- 再分别匹配裁判、物料、租赁、供应商、媒体
- 最终聚合成一个主推荐结果
- 同时输出 1 到 2 个备选方向

推荐结果包含：

- 主馆
- 预算落点
- 方案调性
- 重点项摘要
- 分模块资源卡片
- 备选方向
- 可分享海报内容

## 历史记录与本地存储

所有历史数据都保存在本地 Storage 中，不做云端同步。

存储内容包括：

- 历史推荐记录
- 历史预约记录
- 最近一次需求
- 最近一次分享载荷

相关实现文件：

- `utils/storage.js`
- `utils/share.js`

资源数据主要维护在：

当前资源类型包括：

### 远程图片显示说明

当前资源库和推荐结果中，部分场馆图、裁判头像已经切换为远程 `https` 图片。

要让小程序里稳定显示并参与海报导出，需要同时满足：

1. 图片地址本身可访问
2. 微信小程序后台已将对应域名加入合法域名或下载域名配置
3. 如果图片要参与 `canvas` 海报导出，`wx.getImageInfo` 能正常拉取到该图片

当前使用的远程图片域名是：

- `bee-reg-ab.imagency.cn`

如果你发现资源页能显示、但海报导出仍失败，通常优先排查：

1. 该域名是否已在小程序后台配置
2. 真机调试时该图片地址是否能被 `wx.getImageInfo` 正常获取
3. 是否有个别图片链接失效或被防盗链限制

### 运行注意

- `四库` 文件夹已在 `project.config.json` 中配置为忽略打包
